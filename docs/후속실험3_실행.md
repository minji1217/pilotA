## 0. 먼저 알아야 할 것 — 입력 데이터는 저장소에 없다

아래 네 파일은 **어느 브랜치에도 커밋되어 있지 않다.** 저장소만 받아서는 학습이 돌지 않는다.

| 파일 | 필요한 실험 | 상태 |
|---|---|---|
| `raw/재난프로젝트_시정촌별_통계데이터.xlsx` | 전부 | 커밋된 적 없음 |
| `raw/재난프로젝트_시정촌별_USGS.xlsx` | 전부 | 커밋된 적 없음 |
| `validation/LS_LF 데이터자료.xlsx` | 전부 | `f8bb58b`에서 삭제됨. 히스토리에 남아 있는 판은 2018 훗카이도 1개 이벤트짜리 옛 파일이라 현재 9개 이벤트 코드와 맞지 않는다 |
| `raw/시정촌_면적.csv` | ④ 면적 항 | 커밋된 적 없음 |

그래서 로컬 사본이 있는 폴더를 `--data-dir`로 넘겨야 한다.

```bash
python run_followup3.py --data-dir ~/pilotA-data
```

`--data-dir` 아래 구조는 위 표의 경로 그대로다.

```text
~/pilotA-data/
├── raw/
│   ├── 재난프로젝트_시정촌별_통계데이터.xlsx
│   ├── 재난프로젝트_시정촌별_USGS.xlsx
│   └── 시정촌_면적.csv
└── validation/
    └── LS_LF 데이터자료.xlsx
```

## 1. 한 번에 돌리기

조건마다 브랜치가 다르다. 면적 항은 `prior.py` / `loader.py` 자체가 다르기 때문에
한 checkout에서 전부 돌 수 없다. `run_followup3.py`가 조건별로 `git worktree`를 하나씩
띄우고, 같은 데이터를 심볼릭 링크로 물린 뒤 각 브랜치의 `experiment.py`를 돌린다.

```bash
python run_followup3.py --list                      # 뭐가 돌지 먼저 확인
python run_followup3.py --data-dir <데이터폴더>       # 전체 9조건
python run_followup3.py --group feedback --data-dir <데이터폴더>   # ②만
python run_followup3.py --group area     --data-dir <데이터폴더>   # ④만
python run_followup3.py --only 2 3 --data-dir <데이터폴더>         # 번호로 고르기
python run_followup3.py --epochs 20 --data-dir <데이터폴더>        # 배선 점검용 짧은 실행
```

결과는 아래로 모인다.

```text
outputs/followup3/
├── summary.csv                       전 조건 한 장 비교표
├── <브랜치>.csv                       조건별 요약 + 베이스라인
└── <브랜치>/                          그 조건의 outputs/ 전체
    ├── experiments/params_*.csv
    ├── experiments/eval_detail_*.csv
    ├── experiments/eval_per_event_*.csv
    └── experiments/predictions_*.csv
```

## 2. ② 교수님 피드백 실험

`bounded` 모드의 `b`가 상한에 계속 붙어 나왔다. 그 상태는 최적값을 찾은 것이 아니라
잘라낸 것이므로, 다른 조건은 그대로 두고 **`b` 범위만 넓혀 안쪽에서 멈추는지** 본다.

| # | 이름 | 브랜치 | 복사 원본 | 조건 |
|---|---|---|---|---|
| 1 | 3번 b4 | `followup3-avg-b4` | `followup1-1-wood` (3번) | bounded, lam_gamma=10, b ∈ [-2, 4] |
| 2 | 3번 b10 | `followup3-avg-b10` | `followup1-1-wood` (3번) | bounded, lam_gamma=10, b ∈ [-2, 10] |
| 3 | 6번 b10 | `followup3-lqmax-b10` | `followup2-1-wood` (6번) | LQ prior 최대집계 + bounded, lam_gamma=10, b ∈ [-2, 10] |

브랜치마다 `experiment.py`의 `DEFAULT_PRESET`이 그 조건을 고정한다
(`followup3-area-avg-*`의 `DEFAULT_AREA_MODE`와 같은 방식). 옵션을 손으로 넣지 않아도
브랜치가 뜻하는 조건 그대로 돈다. 기존 그리드를 다시 보고 싶으면 `--preset none`이다.

**b 범위는 비대칭 `[-2, N]`이다.** 넓히려는 쪽은 상한뿐이다. `b`가 상한에 붙어
나온 것이 문제였으므로 하한은 -2로 두고 상한만 4 / 10으로 올린다.
`b_bound` 하나로는 `[-b, +b]`밖에 표현할 수 없어, 이미 `train()`과 `prior.Prior`가
받고 있던 `b_min`/`b_max`를 `experiment.py`까지 이었다. `--b-min` / `--b-max`로
직접 줄 수도 있다(둘 중 하나만 주면 에러).

기존 `PRESETS["followup1"]`(`b_bound=2`) / `["followup2"]`(`b_bound=4`)는 손대지 않았다.
지나간 실험의 조건을 조용히 바꾸면 안 되기 때문이다. 다만 `prior.py` 주석은 후속실험 2의
b 범위를 `[-2, 4]`라고 적어 두었는데 `PRESETS["followup2"]`는 `b_bound=4`, 즉 `[-4, 4]`로
돌고 있다. **주석과 코드가 어긋나 있으니 6번을 다시 돌릴 때 확인이 필요하다.**

같은 checkout에서 b 범위를 바꿔 돌리면 `params_*.csv` / `eval_detail_*.csv`가 서로
덮이므로 프리셋마다 `tag_suffix`로 꼬리표를 갈라 두었고(`bounded_lam10_b10`),
결과 CSV에 `run_tag`와 실제로 쓰인 `b_min` / `b_max` 컬럼을 추가해 어느 범위로 돈 결과인지
CSV만 보고 알 수 있게 했다(`b_bound`는 대칭 범위일 때만 채워지므로 그것만으로는 복원되지 않는다).

## 3. ③ 자연+혼재 재평가 — 아직 못 돈다

학습을 새로 하지 않고 기반 모델(`followup3-avg-b10`, `followup3-lqmax-b10`)의
예측을 재평가하는 작업이다. 브랜치를 따로 만들지 않고 결과 이름으로만 구분한다.

| # | 이름 | 실행 브랜치 | 결과 이름 |
|---|---|---|---|
| 4 | 3번 b10 자연혼재 | `followup3-avg-b10` | `followup3-avg-b10-natmix` |
| 5 | 6번 b10 자연혼재 | `followup3-lqmax-b10` | `followup3-lqmax-b10-natmix` |

**대기 중:** 자연/혼재를 판정할 GT 파일을 받기로 했다. 현재 어느 브랜치에도
"자연 / 인공 / 혼재"를 구분하는 코드가 없고, GT 로더가 읽는 컬럼은 아래가 전부다.

```text
LS : ls_flag  (없으면 ls_area_ha > 0)
LQ : jshis_flag  (없으면 lq_flag)
```

파일을 받아 자연/혼재를 무엇으로 판정하는지(컬럼명과 값)가 확인되면
`loader.py`의 `_prepare_ls_ground_truth()`에 GT 변형 하나를 더하고,
`experiment.py`에 `--gt-variant natmix`를 붙이는 것으로 끝난다. 학습은 그대로 두고
평가 mask만 바뀌므로 위 표대로 기반 브랜치에서 결과 이름만 달리해 돌릴 수 있다.

## 4. ④ 면적 항 실험

`prior.AreaPrior`가 `z = a·log p̄ + b + c·log k`를 쓴다. USGS 값 `p̄`는 발생확률이 아니라
칸 면적 중 덮일 비율이므로, 칸이 독립이면 시정촌에서 한 곳이라도 날 확률은
`1 − exp(−λ)`, `λ = p̄ × k`다. 확률로 넣으면 λ가 클 때 1에 붙어 순위가 사라지므로
순위가 같은 `log λ = log p̄ + log k`를 쓴다. 그래서 `a=1, b=0, c=1`이 유도식 그대로다.

| # | 이름 | 브랜치 | a | b | c | a와 c 관계 | 보는 것 |
|---|---|---|---|---|---|---|---|
| A | fixed | `followup3-area-avg-fixed` | 1 고정 | 0 고정 | 1 고정 | 같게 (고정) | 기준: 유도식 그대로 |
| B | tied | `followup3-area-avg-tied` | 학습 | 학습 [-2,4] | = a | 같게 (학습) | a = c를 지키면서 크기를 학습하면 나아지는지 |
| C | bounded | `followup3-area-avg-bounded` | 학습 | 학습 [-2,4] | 1 고정 | 학습하다 달라짐 | 기존 G2 방식. a만 움직이면 어떻게 되는지 |
| D | free | `followup3-area-avg-free` | 학습 | 학습 [-2,4] | 학습 [0,2] | 둘 다 학습 | 데이터가 a, c를 각자 고르면 어떻게 되는지 |
| E | c 작게 | `followup3-area-avg-a1-c05` | 1 고정 | 0 고정 | 0.5 고정 | 일부러 다르게 (c < a) | 넓은 곳을 감점하면 어떻게 되는지 |
| F | c 크게 | `followup3-area-avg-a1-c2` | 1 고정 | 0 고정 | 2 고정 | 일부러 다르게 (c > a) | 넓은 곳에 가산점을 주면 어떻게 되는지 |

브랜치마다 다른 것은 `train.py`의 `DEFAULT_AREA_MODE` 한 줄뿐이다.

면적 항 조건은 `prior_mode` 축을 쓰지 않으므로 prior 축은 한 번만 돌고,
`lam_gamma`는 브랜치 기본값대로 `0 / 0.1 / 1 / 10` 네 개를 모두 돈다.
②와 직접 비교할 행은 `lam_gamma=10`이다. 한 개만 돌리려면
`--lams 10`을 `run_followup3.py`의 `Run(..., args=("--lams", "10"))`에 넣으면 된다.
